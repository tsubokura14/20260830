# 学習実績可視化アプリ 仕様書

> 本書は [思考プロセス_要件.md](./思考プロセス_要件.md) での検討結果をもとに作成したドラフトです。
> 実装方式に関する決定事項は [技術仕様書.md](./技術仕様書.md) を参照してください。

## 1. 概要・コンセプト

毎日学習をしていても、自分が成長できているのか、意味のあることをできているのか不安になり、
長期目標に対して心が折れそうになることがある。この感情の揺らぎを解消するため、
**学習の積み上げを可視化する**ことを目的としたアプリケーション。

### 1.1 コンセプト（設計思想）

- 本質的な成長度合いを厳密に測ることよりも、**「積み上げた感」を得られること**を優先する。
- 実績の粒度・書く内容の深さはすべてユーザーに委ねる。分かりやすい「達成」だけでなく、
  「前提知識を理解できた」のような、行き場のない粒度の細かい学びも記録できる、
  **その日の学びの棚卸し（日記）**というイメージ。
- ゲーミフィケーション（ストリーク・バッジ・通知等）で記録を煽ることはしない。
  書かない日があってもよく、書いた分がそのまま積み上がって見えることが報酬になる。
- 実績の「量」や「質」をシステム側が判定・採点する仕組みは持たない
  （理解度の%管理、タスクの重み付け、達成度スコアなどは意図的に導入しない）。
  ジャンルの異なる学習を単一の指標で比較するのは本質的に困難であり、
  無理に採点しようとすると正規化・水増し防止といった別の難問を持ち込むことになるため。
- 過去の実績は自由に編集・削除してよい。水増しにインセンティブがない設計のため、
  改ざんを防ぐための特別な制約は設けず、有効に使えるかはユーザーに委ねる。
- 既存のタスク管理（WBS・todo）とは二重管理にしない。本アプリは学習内容そのものや
  タスクの進捗管理を代替するものではなく、それらの過程で得た学びを記録する場とする。

## 2. スコープ

### 2.1 対応する機能

- 実績（学習ログ）の登録・編集・削除
- 実績グループ（ジャンル）の登録・編集・削除
- 実績の可視化（日ごとのリスト表示、期間指定、グループフィルター）
- 実績数の集計・確認（全体／グループ別／インプット・アウトプット別、期間フィルター、ヒートマップ）
- 簡易的なパスワード認証（個人利用・単一ユーザー前提）

### 2.2 対象外（意図的にスコープから外したもの）

| 項目 | 対象外とした理由 |
|---|---|
| 学習内容（教材）そのものとの紐づけ | 紐づける先がない粒度で実績を残したいため。WBS等との二重管理を避ける。 |
| 理解度・達成度の数値管理（%表示等） | 100%の定義が困難で、内部での再正規化など仕組みが複雑になりすぎるため。 |
| タスクの重み・難易度による重み付け表示 | ジャンルを跨いだ単一指標での比較が本質的に困難なため。 |
| todo・WBSなどのタスク管理機能 | 既存のタスク管理と二重管理になるため。実績CRUDに一本化する。 |
| ゲーミフィケーション（ストリーク・バッジ・通知等） | 記録を煽る仕組みは「書かない日があってよい」という設計思想と相反するため。積み上げの実感は可視化画面・実績数確認画面で担う。 |
| サインアップ・複数ユーザー招待機能 | 個人利用・初期ユーザーのみを前提とするため。 |
| パスワードリセット機能 | 個人利用前提のため不要とする。 |

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| 実績 | ユーザーが記録する学習ログ1件。日付・種別・テーマ・内容を持つ。 |
| 実績グループ | 実績を分類するジャンル（例: Java, TypeScript）。表示色を持つ。 |
| 実績種別 | 実績が「インプット」か「アウトプット」かを表す区分。 |
| 未設定グループ | グループ未指定で実績を登録した際に自動的に割り当てられる既定のグループ。 |

## 4. データモデル

### 4.1 ユーザー（users）

| カラム | 型（想定） | 制約 | 備考 |
|---|---|---|---|
| id | serial / uuid | PK | 内部で自動生成 |
| 名前 | varchar(50) | NOT NULL, 1〜50文字 | |
| パスワードハッシュ | varchar | NOT NULL | 平文は保存しない（bcrypt等でハッシュ化）。8文字以上のパスワードから生成 |
| ログイン失敗回数 | integer | NOT NULL, DEFAULT 0 | ログイン試行回数の制限（6章）を実装するためのカラム |
| ロック解除日時 | timestamp | NULL可 | 一時ロック中のみ値を持つ。詳細は[技術仕様書.md](./技術仕様書.md#32-認証)を参照 |

サインアップ機能は設けず、初期ユーザー1件のみを想定する（DBへの直接登録。登録方法の詳細は[技術仕様書.md](./技術仕様書.md#32-認証)を参照）。
パスワードリセット機能も設けない。

### 4.2 実績グループ（achievement_groups）

| カラム | 型（想定） | 制約 | 備考 |
|---|---|---|---|
| id | serial / uuid | PK | 内部で自動生成 |
| ユーザーid | FK → users.id | NOT NULL | |
| 名前 | varchar(300) | NOT NULL, 1〜300文字 | 例: "Java", "TypeScript"。 |
| 色 | varchar | NOT NULL, DEFAULT 'slate' | 表示色。既定値は slate |

システムが用意する既定グループは「未設定」のみとし、それ以外のグループはすべてユーザーが作成する。

### 4.3 実績（achievements）

| カラム | 型（想定） | 制約 | 備考 |
|---|---|---|---|
| id | serial / uuid | PK | 内部で自動生成 |
| ユーザーid | FK → users.id | NOT NULL | |
| グループid | FK → achievement_groups.id | NOT NULL | 未指定時は「未設定」グループを自動割当 |
| 日付 | date | NOT NULL, DEFAULT 当日 | ユーザーが選択可能 |
| 実績種別 | enum('input','output') | NOT NULL | インプット / アウトプットの2値のみ |
| テーマ | varchar(300) | NOT NULL, 1〜300文字 | |
| 内容 | text | NULL可, 0〜3000文字 | 自由記述 |

### 4.4 制約・整合性ルール

- 実績登録時にグループが存在しない、または未指定の場合、実績は自動的に「未設定」グループへ割り当てる。
- 実績グループの削除は、そのグループに紐づく実績が1件でも存在する場合は不可とする
  （PostgreSQLの外部キー制約 `ON DELETE RESTRICT` を想定）。
  実行しようとした場合はエラーとし、UI上で「紐づく実績があるため削除できません」と案内する。
- 実績・実績グループの編集・削除に、日付や作成時刻による制限は設けない（過去分も自由に編集・削除可）。

### 4.5 入力バリデーション

| 項目 | 上限 | 必須 | 備考 |
|---|---|---|---|
| テーマ | 300文字 | 必須 | 前後の空白はトリムしてから文字数判定を行う |
| 内容 | 3000文字 | 任意 | 同上 |
| ユーザー名 | 50文字 | 必須 | 同上 |
| パスワード | 下限8文字 | 必須 | 複雑性（大文字・数字・記号混在）の強制ルールは設けない |

バリデーションはフロントエンド（即時フィードバック）とバックエンド（DB制約含む）の両方で行う。

## 5. 画面一覧

| 画面名 | 概要 |
|---|---|
| ログイン画面 | パスワードによるログインのみ。サインアップ機能は持たない |
| 可視化画面 | 実績を日ごとにリスト表示し、積み上げを確認する（アプリのトップ画面想定） |
| 実績入力画面 | 実績の登録・編集・削除 |
| グループ管理画面 | 実績グループの登録・編集・削除 |
| 実績数確認画面 | 実績の件数集計・期間フィルター・ヒートマップ表示 |

### 5.1 ログイン画面

- パスワードによるログインのみを行う。サインアップ・ユーザー登録機能は持たない。
- 初期ユーザー1件のみを前提とする（個人利用）。

### 5.2 可視化画面

- 実績を**日ごとのリスト形式**で表示する。
- スクロールで日を移動できる。
- 年・月を直接指定できるUIを別途設ける。
- 実績グループによる絞り込み（フィルター）ができる。
- グループごとに表示色を変える。

### 5.3 実績入力画面

- 実績のCRUD（作成・編集・削除）を行う。
- 入力項目: 日付（既定は当日）、実績種別（インプット/アウトプット、必須）、グループ、テーマ（必須、300文字以内）、内容（任意、3000文字以内）。

### 5.4 グループ管理画面

- 実績グループのCRUD（作成・編集・削除）を行う。
- 入力項目: 名前（必須）、色（既定は slate）。
- 紐づく実績が存在するグループは削除不可（4.4節参照）。

### 5.5 実績数確認画面

- 全体の実績数、およびグループ別の実績数を数値の一覧で表示する。
- 日単位・月単位・年単位で実績を集計・可視化できる。
- インプット/アウトプットの内訳も表示する。
- 期間によるフィルターができる。
- **ヒートマップ**をカレンダー形式で表示する。週を7カラムとし、月単位で分割して表示する
  （GitHubのcontribution graphに近いイメージ）。色は実績件数に応じて4段階に分ける
  （0件 / 1件以上 / 5件以上 / 10件以上）。

## 6. 非機能事項（参考）

- 想定スタック: Next.js + PostgreSQL
- 想定利用者: 個人利用前提、単一ユーザー。ただし将来的な拡張に備え、データモデル上はユーザー単位で実績・グループを分離する。
- ログイン試行回数の制限（ブルートフォース対策）を設けることを推奨する。パスワードの複雑性ルールより、
  試行回数制限の方が実効性が高いため（NIST SP 800-63B の考え方に準拠）。
  具体的には5回失敗で15分間ロックする（詳細は[技術仕様書.md](./技術仕様書.md#32-認証)を参照）。
